# SeniorShop 可用性测试方案

## 1. 研究目标

评估 SeniorShop 对老年用户及代理用户的任务完成率、效率、主观可用性（SUS）及协作帮付理解度。

## 2. 被试

| 编号 | 年龄 | 角色 | 说明 |
|------|------|------|------|
| P1 | 62 | 老人代理 | 父母年龄段，熟悉微信 |
| P2 | 58 | 老人代理 | 退休，轻度老花 |
| P3 | 67 | 长辈 | 实际 55+ 用户 |
| P4 | 24 | 代理用户 | 模拟老人操作，事后访谈 |
| P5 | 28 | 代理用户 | 产品经理背景 |
| P6 | 71 | 长辈 | 实际 55+ 用户 |

共 6 人：2 位 55+ 长辈 + 4 位代理用户（局限在报告中说明）。

## 3. 知情同意要点

- 测试约 30–40 分钟，可随时退出
- 数据匿名，仅用于课程项目
- 允许录屏/笔记，不公开个人手机号

## 4. 测试环境

- 设备：Chrome 浏览器，手机或笔记本
- 网络：本地服务器 `http://localhost:3000`
- 辅助：观察员在场，仅在受试者明确求助时提示

## 5. 任务设计

| 任务 | 角色 | 说明 | 成功标准 |
|------|------|------|----------|
| **T1** 注册并进入购物首页 | 老人 | 选择「我是老人」→ 注册 → 登录 | 看到首页 4 分类 |
| **T2** 找到并加入纯牛奶 | 老人 | 用找找或语音加购 | 购物车出现纯牛奶 |
| **T3** 提交待付订单 | 老人 | 购物车 → 去付钱 | 订单状态 pending |
| **T4** 子女完成帮付 | 子女 | 登录子女账号 → 帮付 | 订单变 paid |

**测量指标**：完成时间（秒）、错误次数、是否求助（Y/N）、是否理解「等着我付」（T3 后 1–5 分）

## 6. SUS 量表（测试后填写）

标准 10 题 System Usability Scale，每题 1–5 分。  
计分公式：`SUS = (各题得分之和) × 2.5`（奇数题减 1，偶数题用 5 减后求和再 ×2.5）

## 7. 半结构访谈（3 题）

1. 哪里最安心？哪里最困惑？
2. 敢不敢自己付？为什么？
3. 帮付模式是否理解？子女端体验如何？

## 8. 观察员记录表

| 字段 | 说明 |
|------|------|
| task_id | T1–T4 |
| success | 0/1 |
| time_sec | 秒 |
| errors | 误点、说错命令等 |
| help_requested | 是否主动求助 |
| notes | 原话摘录 |
