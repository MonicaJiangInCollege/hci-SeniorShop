# Companion Cart 答辩叙事（15–20 分钟）

## 封面定位

> **Companion Cart：面向老年人与视障用户的 AI 协同购物助手**  
> 老人或视障用户只需说话即可购物，AI 朗读与筛选风险，家人共同确认付款。

---

## 1. 场景开场（2 min）

不要先说“我们做了一个购物平台”，先抛出问题：

> 很多老年人并不是不会点按钮，而是不敢独自完成购物。对视力下降或视障用户来说，复杂电商界面更像一堵墙。我们希望让他们只靠说话，就能安全地完成购物，并在需要时获得家人的协同支持。

主演示用户：**张阿姨，68 岁，视力下降，想买一个电子血压计，但看不清商品信息，也不敢直接付款。**

## 2. 核心论点（2 min）

Companion Cart 不是“老人版淘宝”，而是重新分配购物任务：

- 用户负责表达生活需求，例如“我想买血压计”。
- AI 小伴负责理解需求、朗读商品、解释推荐与风险。
- 家人负责审核高风险节点并远程付款。

答辩关键词：**不是让老人适应电商，而是让电商适应看不清、点不准、不敢付的人。**

## 3. 理论背书（3 min）

| HCI 概念 | Companion Cart 落地 |
|----------|---------------------|
| Accessibility | 低视力/盲人模式、高对比、单焦点、TTS 朗读 |
| Multimodal Interaction | 语音表达 + 视觉确认 + 朗读反馈 |
| Human-AI Collaboration | AI 理解需求、筛选商品、解释风险 |
| CSCW | 老人、AI、子女共同完成购物决策 |
| Trustworthy UX | 药品、保健品、大额订单给出原因再交给家人 |

详见 [`hci-theory-backing.md`](hci-theory-backing.md) 与 [`design-principles.md`](design-principles.md)。

## 4. 主演示路径（6 min）

1. 老人端首页展示 Companion Cart：小伴在听、任务状态、低风险入口。
2. 点击“我看不清，语音帮我买”，进入黑底高对比单卡片模式。
3. 用户说“小伴，我想买血压计”。
4. 系统朗读商品名称、价格、用途，用户说“下一个”“读一遍”或“放进清单”。
5. 用户说“让孩子看看”，系统朗读清单、金额和风险原因。
6. 用户说“确认提交”，订单进入家庭守护台。
7. 子女端看到“低视力/盲人模式”“语音提交”“小伴风险解释”，审核后付款。
8. 老人端收到“家人已确认付款”的反馈。

## 5. 对比补充（2 min）

普通电商默认用户看得清、点得准、能理解促销和支付流程；Companion Cart 默认用户可能看不清、点不准、不敢付，因此把核心交互变成“说话购物 + 朗读确认 + 家庭协同”。

## 6. 可用性评估与迭代（3 min）

**被试**：6 人（2 位 55+ 长辈 + 4 位代理用户）

| 指标 | 结果 |
|------|------|
| SUS 平均分 | **82.5**（高于行业平均 68） |
| 任务成功率 | **91.7%**（22/24 任务） |
| T2 平均耗时 | 比淘宝对照缩短 **38%** |

**迭代案例**：语音结算可能误提交 → 统一安全结算函数 → 必须朗读清单、金额和风险，并要求“确认提交”。

详见 [`docs/evaluation/`](../evaluation/README.md)。

## 7. 总结三句话

1. Companion Cart 用极端无障碍场景验证适老化：看不清也能买。
2. AI 不是聊天装饰，而是负责理解、朗读、筛选和解释。
3. 子女不是简单代付，而是家庭协同购物中的安全审核者。
