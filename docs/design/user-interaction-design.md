# Companion Cart — 用户交互设计文档

> **面向老年人与视障用户的 AI 协同购物助手**  
> 老人或视障用户只需说话即可购物，AI 朗读与筛选风险，家人共同确认付款。

---

## 一、项目概述

**Companion Cart** 是一款专为老年人和视障用户设计的语音优先购物助手。与传统电商不同，它不以"功能丰富"为目标，而是围绕"看不清、点不准、不敢付"三个核心痛点，重新设计购物交互流程。

| 维度 | 设计决策 |
|------|----------|
| **目标用户** | 68岁退休老人（老花眼、手颤、怕误操作）+ 异地子女 |
| **核心交互** | 语音表达需求 → AI理解筛选 → 朗读确认 → 家人协同付款 |
| **设计哲学** | 不让老人适应电商，让电商适应看不清、点不准、不敢付的人 |
| **评估结果** | SUS 82.5（优秀），任务成功率 91.7%，比淘宝快 38% |

## 四、核心交互流程

### 4.1 完整购物链路（老人端 → 子女端）

```
┌─────────────────────────────────────────────────────────┐
│ 老人端                              │ 子女端             │
│                                     │                    │
│ ① 唤醒小伴 "你好小伴"               │                    │
│     ↓                               │                    │
│ ② 表达需求 "我想买血压计"           │                    │
│     ↓                               │                    │
│ ③ AI筛选商品 → TTS朗读             │                    │
│    "电子血压计，138元，一键测量…"    │                    │
│     ↓                               │                    │
│ ④ 浏览确认 "下一个" / "读一遍"      │                    │
│     ↓                               │                    │
│ ⑤ 加入清单 "放进清单"              │                    │
│     ↓                               │                    │
│ ⑥ 提交结算 "让孩子看看"            │                    │
│    [系统朗读清单+金额+风险]          │                    │
│     ↓                               │                    │
│ ⑦ 等待确认 "等着我付"               │ ──→  待付通知       │
│                                     │       ↓             │
│                                     │  ⑧ 查看订单详情     │
│                                     │     [来源标记]       │
│                                     │     [风险解释]       │
│                                     │     [老人留言]       │
│                                     │       ↓             │
│ ⑨ 收到反馈 "已在路上" ←────────    │  ⑨ 确认代付         │
│    TTS播报完成                      │                    │
└─────────────────────────────────────────────────────────┘
```

### 4.2 页面导航体系

```
入口（身份选择）
  ├── 老人端首页 (page1)
  │     ├── 搜索框 → 搜索结果 (page8)
  │     ├── 食品饮料 (page2) → 子分类筛选 → 商品详情 (page10)
  │     ├── 日用品   (page3) → 子分类筛选 → 商品详情 (page10)
  │     ├── 药品保健 (page4) → 子分类筛选 → 商品详情 (page10)
  │     ├── 随便看看 (page5) → 推荐区 + 全部商品
  │     ├── 购物车   (page6) → 选择地址 → 安全结算
  │     ├── 我的订单 (page9) → 物流进度追踪
  │     ├── 我收藏的 (page12) → 收藏商品列表

  │     ├── 商品对比 (page13) → 双商品并排比较
  │     └── AI浮动聊天（全场景可用）
  └── 子女端家庭守护台 (page7)
        ├── 待付订单 → 查看详情 → 代付
        └── 已付记录
```

## 五、多模态交互设计

### 5.1 语音交互

#### 唤醒词检测
系统持续监听唤醒词，无需点击即可激活：

| 唤醒词 | 响应 |
|--------|------|
| "你好小伴" | 激活AI导购，进入语音对话模式 |
| "嗨小伴" | 同上 |
| "小伴" | 同上 |

#### 语音指令集

| 类别 | 指令示例 | 系统行为 |
|------|----------|----------|
| 导航 | "去食品"、"去日用品"、"去药品" | 跳转到对应分类页 |
| 搜索 | "买牛奶"、"找血压计" | 搜索商品并朗读结果 |
| 加购 | "放进清单"、"加入购物车" | 将当前商品加入购物车 |
| 浏览 | "下一个"、"上一个"、"读一遍" | 低视力模式下切换/朗读商品 |
| 结算 | "让孩子看看"、"确认提交" | 进入安全结算流程 |
| 退出 | "再见"、"关闭" | 关闭AI对话 |

#### 语音反馈（TTS）

- **百度语音合成**：主 TTS 引擎，自然女声
- **浏览器 Web Speech API**：备用引擎
- 所有 AI 回复、商品信息、风险提醒均可朗读
- 页面朗读按钮：一键朗读当前页面全部内容

### 5.2 视觉交互

#### 适老化视觉设计

| 元素 | 标准模式 | 低视力模式 |
|------|----------|------------|
| 基础字号 | 20px（可调至16/24/28px） | 34px |
| 价格字号 | 20px | 36px |
| 按钮高度 | 48-56px | 56-68px |
| 配色 | 米白底(#FFF8F0) + 橙色主调 | 黑底(#1a1a1a) + 黄色字(#FFD54F) |
| 信息密度 | 2列商品网格 | 单卡片，一次只看一个商品 |

#### 字体大小调节

用户可随时通过首页 A+/A- 按钮调节字号，系统自动记忆偏好：

| 档位 | 基础字号 | 适用人群 |
|------|----------|----------|
| 小 | 16px | 视力较好的用户 |
| 标准 | 20px | 一般老花眼 |
| 大 | 24px | 中度视力下降 |
| 超大 | 28px | 重度视力障碍 |

#### 低视力/盲人模式

专为严重视力障碍设计的纯语音+单卡片交互：
- 黑底黄字，极致对比度
- 每次只展示一个商品
- 大按钮："上一个"、"下一个"、"读一遍"、"放进清单"、"让孩子看看"
- 所有操作均有 TTS 语音反馈
- 支持纯语音操作，无需看屏幕

### 5.3 触控交互

| 场景 | 设计要点 |
|------|----------|
| 分类入口 | 4个大按钮（120px高），2×2网格，带emoji图标 |
| 子分类筛选 | 圆形药丸按钮，点击高亮为橙色 |
| 商品卡片 | 点击进入详情页，卡片hover有浮起动效 |
| 加入购物车 | 每张卡片和详情页都有醒目按钮 |
| 收藏 | ♡ 按钮，红心=已收藏，点击切换 |
| 商品对比 | 勾选框 + 浮动"开始对比"按钮 |

## 六、AI 导购交互设计

### 6.1 AI 小伴的角色定位

AI 小伴不是聊天装饰，而是在购物任务中承担明确职责的协作者：

| 职责 | 具体行为 |
|------|----------|
| **理解需求** | 将自然语言转为商品搜索意图 |
| **筛选商品** | 从50件商品中匹配最佳结果 |
| **朗读解释** | 用短句朗读名称、价格、用途 |
| **风险提醒** | 药品、保健品、大额订单给出解释 |
| **状态传递** | 将订单来源和风险传给家庭守护台 |

### 6.2 全场景 AI 聊天

- **浮动按钮**：所有商品页面右下角固定显示 🤖 按钮
- **弹窗聊天**：点击打开，支持文字和语音输入
- **意图识别**：AI 自动识别"加入购物车"、"去结算"、"搜索商品"三类意图
- **商品链接**：AI 回复中的 `【商品名】` 可点击直接跳转到详情页
- **快捷问题**：预设 4 个常用问题一键提问
- **上下文感知**：AI 知道用户当前在哪个页面、看到哪些商品

### 6.3 购物车 AI 建议

在购物车页面，AI 可分析清单并提供购买建议：
- 对已选商品的总体评价
- 建议搭配购买的商品
- 提醒可能遗漏的必需品
- 语气亲切温暖，适合老年人

## 七、家庭协同交互（CSCW）

### 7.1 亲子账户绑定

- 子女注册时输入父母手机号，系统自动建立绑定关系
- 一个子女可绑定一个老人，绑定关系存储在用户数据中
- 子女登录后仅看到自己父母的订单

### 7.2 子女端"家庭守护台"

区别于普通订单列表，子女端的设计强调"守护"而非"管理"：

| 信息展示 | 目的 |
|----------|------|
| 订单来源标记（触屏/语音/AI） | 了解老人用什么方式下单 |
| 辅助模式标记（标准/低视力） | 判断老人当下的视觉状态 |
| 安全风险说明 | 药品、大额订单的详细解释 |
| 老人语音留言 | 听到老人的原声需求 |
| 智能提醒摘要 | AI 给出的风险归纳 |

### 7.3 通知机制

- 子女端"今日待确认"标签上显示待付订单数量的红点徽章
- 数字实时更新，无需手动刷新
- 已付记录独立标签页展示

## 八、安全结算交互设计

### 8.1 安全检测规则

| 触发条件 | 响应 |
|----------|------|
| 含药品/保健品/医疗器械 | 标红提醒，列出具体商品 |
| 订单金额 ≥ 100元 | 金额高亮提醒 |
| 语音/AI模式提交 | 额外朗读确认 |

### 8.2 统一安全结算路径

无论用户通过触屏、语音还是 AI 触发结算，都经过同一个安全确认函数，确保：
1. TTS 朗读购物清单
2. 朗读合计金额
3. 如有风险，朗读风险原因
4. 要求用户明确确认"确认提交"
5. 订单提交后自动通知子女

### 8.3 收货地址验证

- 结算前必须选择收货地址
- 子女可为老人预设默认地址
- 地址信息大字号展示，老人只需点选

## 九、商品交互功能详解

### 9.1 分类与子分类浏览

| 大类 | 子分类 |
|------|--------|
| 🥤 食品饮料 | 饮品 / 主食 / 零食干货 / 调味品 |
| 🧹 日用品 | 纸品家清 / 个人护理 / 厨房用品 / 老年辅具 |
| 💊 药品保健 | 保健滋补 / 医疗器械 / 防护卫生 / 外用护理 |

点击大类进入子分类页，顶部药丸按钮切换筛选，即时刷新商品列表。

### 9.2 商品详情页

点击任意商品进入详情，展示：
- 大号 emoji / 实物图片（160px）
- 商品名称、价格、标签
- 完整详细描述（约 80 字）
- 收藏按钮（❤️）
- 加入对比勾选框
- 用户评价区（星级 + 标签 + 文字）
- 写评价入口

### 9.3 商品对比

- 任意商品卡片可勾选"对比"
- 最多选 2 个，浮动栏实时显示已选数量
- 对比页并排展示两个商品：emoji、名称、价格、详细描述、标签
- 价格更低的一方自动标记"✓ 更实惠"

### 9.4 收藏功能

- 商品卡片和详情页均有收藏按钮（🤍/❤️）
- 首页"我收藏的"入口直达收藏页
- 收藏商品可直接加入购物车

### 9.5 常买清单

- 系统分析用户历史订单，提取最常购买的商品（top 6）
- 首页展示"常买清单"区域
- 一键将全部常买商品加入购物车

### 9.6 搜索

- 大号搜索框（56px高），placeholder "搜索您想要的商品"
- 模糊匹配：商品名称、描述、分类、标签
- 支持多关键词（空格分隔）
- 搜索行为自动记录，用于个性化推荐

## 十、订单与物流交互

### 10.1 订单状态可视化

五阶段物流进度条：

```
📝 已提交  →  💰 已付款  →  📦 已发货  →  ✅ 已送达  →  🏠 已完成
```

- 点击已付款订单可展开查看进度条
- 已发货订单显示物流描述文字
- 已发货订单显示快递单号

### 10.2 订单列表

- 按时间倒序排列
- 待付款订单标注"等子女付款中..."
- 已付款订单可点击展开物流详情
- 每笔订单显示：商品列表、合计金额、提交时间

## 十一、个性化推荐交互

### 11.1 推荐算法

混合打分，综合四个维度：

| 维度 | 权重 | 说明 |
|------|------|------|
| 品类偏好 | 35% | 用户浏览/搜索最多的商品类别 |
| 关键词匹配 | 25% | 搜索词与商品信息的相关度 |
| 协同过滤 | 20% | 所有用户的购物车/订单热门商品 |
| 老年适用 | 20% | 标记为 elderlyFriendly 的商品加权 |

### 11.2 推荐展示

- **冷启动**：新用户推荐老年适用商品 + 全局热门
- **个性化**：根据浏览和搜索行为动态调整
- **去重**：已加入购物车的商品不再推荐
- **展示位置**："随便看看"页面顶部"猜您喜欢 ❤️"区域

## 十二、可用性评估

### 12.1 测试设计

| 项目 | 详情 |
|------|------|
| 被试 | 6人（2位55+长辈 + 4位代理用户） |
| 任务数 | 4个（注册登录 / 加购纯牛奶 / 提交待付 / 子女帮付） |
| 对比基准 | 淘宝App同任务（代理用户子集） |
| 评价工具 | SUS量表 + 任务成功率 + 完成时间 |

### 12.2 测试结果

| 指标 | Companion Cart | 行业/对照 |
|------|----------------|-----------|
| SUS 平均分 | **82.5**（优秀） | 行业平均 68 |
| 任务总成功率 | **91.7%** | — |
| T2 加购纯牛奶 | **88s** | 淘宝 142s（快38%） |
| T4 子女帮付 | **49s** | — |

### 12.3 关键迭代

> **问题**：语音结算可能误提交  
> **改进**：统一所有结算入口走同一个安全确认函数 → 必须朗读清单、金额和风险 → 要求明确"确认提交"

## 十三、设计原则总结

| 原则 | 核心体现 |
|------|----------|
| **说话优先** | 唤醒词 + 全场景AI聊天 + 纯语音购物模式 |
| **看不清也能买** | 低视力模式 + 字体4档调节 + TTS朗读全覆盖 |
| **少而明确** | 4大分类 + 子分类筛选 + 单卡片浏览 |
| **AI有职责** | 理解需求、筛选商品、朗读解释、标记风险 |
| **家庭协同** | 亲子绑定 + 家庭守护台 + 来源/模式/风险全透明 |
| **风险可解释** | 药品/大额/语音提交 → 原因说明 → 子女审核 |
