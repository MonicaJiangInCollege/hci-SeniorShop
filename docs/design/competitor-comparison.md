# 竞品对比：主流电商 vs SeniorShop

## 对比维度

| 维度 | 淘宝/京东首页 | SeniorShop | Nielsen 启发式关联 |
|------|--------------|------------|-------------------|
| **信息密度** | 一屏 20+ 入口、轮播、促销 | 首页仅 4 分类 + 购物车 + 订单 | 简约与美学：降低认知负荷 |
| **术语** | 秒杀、领券、凑单、SKU | 找找、我选好的东西、等着我付 | 系统与现实匹配 |
| **触控目标** | 小图标、密集列表 | 120×120 分类格、80px 导航按钮 | 灵活性与效率（适老放大） |
| **支付流程** | 老人需绑卡、输密码、人脸识别 | 提交待付 → 子女帮付 | 容错：避免不可逆误操作 |
| **多模态** | 以视觉为主，语音助手边缘化 | 语音唤醒 + TTS + 视觉互补 | 多通道信息呈现 |
| **协作** | 无原生代际协作 | 亲子绑定 + 帮付中心 + 安全提醒 | 以用户为中心的安全设计 |

## 关键页面对比（Before / After）

### 首页

| 淘宝/京东 | SeniorShop |
|-----------|------------|
| 搜索框 + 10+ 功能图标 + 直播 + 促销横幅 | 「您想买点什么？」+ 4 大分类 Emoji 按钮 |
| 需理解「购物车」「优惠券」「会员」 | 「我选好的东西」「我买的东西」通俗说法 |
| 支付入口显眼，误触风险高 | 无直接支付，仅「让子女帮忙付」 |

### 结算

| 淘宝/京东 | SeniorShop |
|-----------|------------|
| 地址 → 优惠券 → 支付方式 → 确认付款 | 购物车 → 去付钱 → 待付状态 |
| 老人独自完成支付 | 老人表达意图，子女完成支付决策 |

### 药品/大额场景

| 淘宝/京东 | SeniorShop |
|-----------|------------|
| 无特殊提醒 | 自动检测药品/大额，提醒子女关注 |

## 为何不简单缩小版淘宝？

主流电商 UI 对老年人是**负向设计**：

1. **可见性违反**：重要操作淹没在促销信息中
2. **匹配性违反**：电商术语与老人日常语言不匹配
3. **容错性违反**：一键支付缺少二次确认的安全网
4. **一致性违反**：各频道入口逻辑不统一

SeniorShop 选择**场景驱动的适老化**，而非通用 App 的缩小版。

## 答辩用一句话

> 我们不是把淘宝做小，而是为「老人敢选、子女帮付」重新设计交互模态。
