# HCI 理论背书：Companion Cart

## 1. Accessibility & Inclusive Design

**理论依据**：无障碍设计强调系统应适配能力差异，而不是要求用户适应复杂界面。对老年人与低视力用户，购物障碍不仅是字体小，还包括信息密度高、焦点分散、误触后果不明确。

**设计落地**：

| 原则 | Companion Cart 实现 |
|------|---------------------|
| 高可见性 | 黑底高对比、超大字号、粗边框 |
| 单焦点 | 低视力模式每次只呈现一个商品 |
| 朗读反馈 | 商品、价格、清单、金额和风险都可 TTS |
| 低认知负荷 | 首页突出“说话购物”，保留少量低风险入口 |
| 可逆与确认 | 提交前必须朗读清单，并要求确认提交 |

## 2. Multimodal Interaction

**理论依据**：Norman 与 Oviatt 的多模态交互研究指出，不同通道适合承担不同任务。语音适合表达意图，视觉适合状态确认，听觉适合低视力用户获得反馈。

| 任务类型 | 主模态 | 辅模态 | 示例 |
|----------|--------|--------|------|
| 表达需求 | 语音 | AI 对话 | “我想买血压计” |
| 浏览选择 | 朗读 | 单卡片视觉 | “下一个”“读一遍” |
| 加入清单 | 语音/大按钮 | TTS 反馈 | “放进清单” |
| 结算确认 | TTS + 语音确认 | 视觉安全卡 | “确认提交” |
| 付款审核 | 子女视觉操作 | 风险解释 | 家庭守护台 |

## 3. Human-AI Collaboration

AI 小伴不是单纯客服，而是在任务中承担明确职责：

- 将自然语言需求转为商品搜索与推荐。
- 用短句朗读商品名称、价格、用途。
- 对药品、保健品、医疗器械和大额订单给出解释型提醒。
- 将订单来源和风险原因传给家庭守护台。

这种分工让用户保留意图控制权，同时把筛选、解释和记忆负担交给系统。

## 4. CSCW 与分布式认知

**理论依据**：CSCW 关注多人如何通过系统协同完成任务；分布式认知认为认知负荷可以分布在用户、工具和他人之间。

Companion Cart 的协作模型：

```
老人/视障用户：表达需求、选择是否加入清单
AI 小伴：理解、朗读、筛选、解释
子女/家人：审核风险、远程付款、必要时退回确认
```

子女不是“代替老人操作”，而是承担高风险节点的共同决策角色。

## 5. Trustworthy UX 与安全关键交互

**触发条件**：

- 药品、保健品、医疗器械或健康用品。
- 金额超过阈值。
- 语音或低视力模式提交，存在误听、误选可能。

**响应方式**：

- 提交前朗读清单和金额。
- 统一点击、语音和 AI 结算路径，避免绕过确认。
- 子女端展示来源、辅助模式、风险解释和老人留言。
- 付款按钮文案强调“确认无误，帮家人付”。

## 6. UCD 闭环

```
Persona → 极端用户场景 → 原型 → 可用性测试 → 安全确认迭代
```

极端场景是“看不清也能买”。当低视力/盲人模式能够完成购买，普通老人使用时认知负担也会降低。

详见 [`docs/evaluation/`](../evaluation/README.md)。

## 答辩三句话创新点

1. **Accessibility**：用低视力/盲人模式验证核心购物链路。
2. **Human-AI Collaboration + CSCW**：用户、AI、家人共同完成购物决策。
3. **Trustworthy UX**：风险提醒说明原因，并进入家庭审核闭环。
